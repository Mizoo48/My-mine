git push -u origin Main.. # AI Cartoon Video Agent - Infrastructure & Database Design (v0.1)

## 1. Components
| Component | Role | MVP choice | Scale-up choice |
|---|---|---|---|
| Web UI | Create projects, edit character bible, review/approve shots | Next.js or simple React app | Same, behind a CDN |
| API | Auth, CRUD, starts agent runs, receives provider webhooks | FastAPI (Python) | Same, 2+ replicas behind a load balancer |
| Orchestrator / workers | Runs the pipeline steps; resumes after crashes | Celery or Arq + Redis | Temporal (durable workflows) |
| Queue / cache | Job queue, rate limiting, short-lived locks | Redis | Managed Redis / SQS |
| Database | All metadata, state, costs | PostgreSQL 16 (container) | Managed Postgres (RDS, Neon, Supabase) + read replica |
| Object storage | Images, clips, audio, final renders | MinIO (S3-compatible) | S3 / Cloudflare R2 / Backblaze B2 + CDN |
| Media workers | ffmpeg: trim, concat, mix audio, burn subtitles, thumbnails | CPU container | Autoscaled CPU pool |
| Provider adapters | One class per external API (image, video, TTS, music, LLM, vision QA) | In the worker code | Same, with per-provider rate limits |
| GPU pool (optional) | Self-hosted open video model | none | GPU instances, only if volume justifies it |
| Observability | Logs, metrics, error tracking, cost dashboard | Structured logs + Sentry | Prometheus/Grafana or a hosted APM |
| Secrets | Provider keys, DB password | .env (local only) | Secrets manager (AWS SM, Vault, Doppler) |

## 2. Data flow (one film)
1. `projects` row created -> `characters` + `character_references` (reference images stored as `assets`).
2. Agent run `script`: LLM writes a script -> `scripts` (versioned) -> human approves.
3. Run `storyboard`: script split into `scenes` and `shots` (each 1-15 s), characters linked in `shot_characters`.
4. Run `keyframes`: per shot, a `generations` row (kind=keyframe) -> provider call -> `assets` -> `shots.keyframe_asset_id`.
5. Run `clips`: per shot, `generations` (kind=clip) from the keyframe + references -> `assets` -> `shots.clip_asset_id`.
6. `qa_checks`: vision model scores character consistency / artifacts. Below threshold -> new generation (attempt+1, up to `MAX_GENERATION_RETRIES`).
7. Run `audio`: music / SFX / (optional) voice -> `assets` + `audio_tracks` timeline.
8. Human review: `shots.status = approved/rejected` (run status `waiting_for_review`).
9. Run `render`: ffmpeg builds the final video from the `renders.timeline` JSON -> `assets` (kind=render).

## 3. Rules that keep the system safe and cheap
- **Idempotency:** `generations.idempotency_key` is unique. A retried task can never create (and pay for) a duplicate call.
- **Budget guard:** before each paid call the worker reads `project_cost_summary`. If `remaining_usd` is less than the estimated cost, the run pauses with an `agent_events` entry `budget_warning`.
- **Async providers:** store the provider's `external_job_id`; finish via webhook, with a polling fallback every 10-30 s.
- **Resumable runs:** the pipeline writes its checkpoint to `agent_runs.state`; a restarted worker continues from it.
- **Preview first:** generate cheap low-resolution drafts; re-render only approved shots at final quality.
- **Dedupe:** `assets.sha256` is unique per project, so identical files are stored once.
- **Soft delete + retention:** `projects.deleted_at`; an object-storage lifecycle rule deletes rejected takes after N days.
- **Reproducible exports:** `renders.timeline` stores exactly which clips and audio were used.

## 4. Security checklist
- Provider API keys only in a secrets manager; the DB stores just `providers.secret_ref`.
- Private bucket; give the browser short-lived signed URLs, never public links.
- Per-user ownership checks on every query (or Postgres Row-Level Security).
- Webhook endpoints verify the provider's signature.
- Content moderation step before generation and before publishing.
- Backups: daily Postgres snapshots + point-in-time recovery; test a restore.
- Keep the original characters you created: do not feed copyrighted characters (for example Tom and Jerry) into prompts or reference images.

## 5. Deployment tiers
1. **Local / MVP:** `docker compose up` (Postgres, Redis, MinIO) + API + 1-2 workers on one VPS.
2. **Small production:** managed Postgres, S3/R2 + CDN, API and workers as containers (Fly.io, Render, ECS), Sentry.
3. **Scale:** Temporal, autoscaled worker pools per task type (LLM / provider calls / ffmpeg), optional GPU pool, read replica for dashboards.
